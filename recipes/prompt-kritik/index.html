Промпт-паттерн «Критик»: заставить модель спорить с собой

Два прохода вместо одного: генератор пишет, критик ищет дыры, редактор чинит. Промпт, который ловит ошибки до того, как их поймает ревьюер.

Одна модель, один проход — один средний результат. Просить «проверь себя» бесполезно: модель уже уверена, что написала хорошо. Нужна смена роли и отдельный контекст.

Паттерн простой: генерация → критика → правка. Три вызова, три разные инструкции. Работает и в чате, и в коде, и в текстах.

Промпт

Шаг 1 — генератор:

Ты — старший инженер. Реши задачу ниже.

Задача: {{task}}
Контекст: {{context}}

Требования:
- предложи 2 варианта решения
- для каждого: плюсы, минусы, стоимость поддержки
- не пиши код, только план

Верни ответ в markdown, без вступлений.

Шаг 2 — критик. Новый чат, на вход только результат первого шага:

Ты — ревьюер, который не доверяет автору.

Ниже — план решения. Найди:
1. скрытые допущения
2. места, где решение сломается при нагрузке x10
3. чего не хватает для реализации
4. альтернативу, которую автор не рассмотрел

Не хвали. Не переписывай. Только список проблем,
отсортированный по серьёзности. Максимум 7 пунктов.

План:
{{plan}}

Шаг 3 — редактор возвращается к первому контексту:

Вот твой план и критика к нему.

Перепиши план: убери пункты, которые не выдержали критику,
добавь пропущенное. Для каждого исправления укажи,
какой пункт критики его вызвал.

План: {{plan}}
Критика: {{critique}}

Почему это работает

  • Смена роли меняет распределение. Критик не обязан быть согласованным с генератором.
  • Разный контекст. Во втором чате нет вашего «я уже полчаса объясняю, что мне нужно» — есть только текст.
  • Явный список. «Найди 7 проблем» выполняется лучше, чем «проверь качество».
  • След правок. Третий шаг заставляет связать критику и изменение, а не переписать всё заново.

Где ломается

  • Критик без критериев выдаёт общие слова: «недостаточно тестов», «можно улучшить». Дайте ему область: нагрузка, безопасность, стоимость, поддержка.
  • Один чат на все три шага. Модель видит свои прошлые аргументы и защищает их. Разносите.
  • Критика без редактора. Получите список проблем и ноль решений. Третий шаг обязателен.
  • Задачи на вкус. «Сделай красиво» не имеет правильного ответа. Паттерн для проверяемых вещей: код, планы, тексты с фактами.

Вариация для кода: генератор пишет реализацию, критик получает только diff и тесты — без объяснений автора. Если критик не понимает, что делает код, ревьюер тоже не поймёт.

Мини-версия на один запрос

Если лень настраивать три шага, используйте один промпт, но с жёсткой структурой:

Ответь в три блока:
1. РЕШЕНИЕ — кратко
2. КРИТИКА — 5 причин, почему это может не сработать
3. ИТОГ — что меняем после критики

Не пропускай блок 2. Если проблем нет — значит, ты плохо искал.

Это слабее полноценного паттерна, но лучше, чем ничего. Главное — не давать модели закрыть задачу с первого прохода.
